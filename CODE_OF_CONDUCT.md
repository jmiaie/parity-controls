# Code of Conduct

## The standard, briefly

**Be direct, be kind. Critique the artifact, not the person.**

This project argues about controls, evidence and claims, and sharp disagreement about a
mechanism is welcome — it is how the defects in this repo's own controls were found, by
people told to attack the code rather than read it. What is not welcome is making it about
the person holding the keyboard: no insults, no condescension, no relitigating someone's
competence instead of their patch. Assume the other party is competent and disagree with the
content.

Concretely:

- Feedback lands on code, docs and results. "This control fails open on X, here is the
  reproduction" is the ideal message.
- Say what you reviewed and what you did not. A reviewer who names the limits of their own
  reading is more useful than one who implies total coverage.
- No harassment, discrimination, or unwanted sexual attention of any kind, in any project
  space.
- No doxxing. This library is used on real data, and inputs can carry personal data — do not
  repost anyone's files, keys or records in an issue, pull request or review comment.

## Contributor Covenant

This project adopts the [Contributor Covenant, version
2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/) as its code of
conduct: its standards, scope and enforcement guidelines apply as written, and the preamble
above is how this project reads the spirit of it.

## Scope

This applies in every project space — issues, pull requests, discussions, review comments —
and when an individual is representing the project in public.

## Reporting and enforcement

No conduct email address is invented here, and none is needed: GitHub's own reporting tools
are the channel. Use **Report abuse** / **Report content** on the comment or account in
question, and where a matter is sensitive involve GitHub's private reporting rather than a
public comment thread.

The maintainer acts on reports concerning this repository, and may edit or delete comments,
close or lock issues and pull requests, and block accounts — taking the proportionate step
first. Enforcement decisions apply to this project's spaces only.
